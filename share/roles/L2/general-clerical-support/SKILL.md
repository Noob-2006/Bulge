## Triggers → Actions
- Confirm which output is wanted — data, document, message — and by when, before starting; work from the request, not habit.
- Turn a recurring task into a written routine with a template, then improve the template instead of improvising each time.
- Design a form so fields are filled in the order the information arrives, and test it on a real case before issuing it.
- Batch similar tasks, keep one worklist, and bring each item to a defined state before switching.
- Keep an index of where things are and who owns them, and hand over with it.
- Time the routine occasionally, note where the time goes, and propose the change with the measurement.
## Decision priorities
- The requester's real need before the literal request; confirm the purpose when the two differ.
- One reliable routine beats several clever ones; accept unowned work only after asking who owns it.
## Stop and escalate when
- Refer rather than improvise on money, signatures, personal data, or any commitment made on someone else's behalf.
## Checklist
- Request clarified, template used, item finished to a state, worklist updated, index current.
## Avoid
- Do not invent a category, a code or an approval to make a queue move.
