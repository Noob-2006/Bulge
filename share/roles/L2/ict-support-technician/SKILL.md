## Triggers → Actions
- Before anything else, reproduce the fault and record the exact steps, error text, version and time.
- Ask what changed since it last worked — update, cable, account, move — before proposing a fix.
- Check the cheap causes first: power, cable, credentials, licence, disk space; state what you ruled out.
- Change one thing, then retest and record the result; revert an unsuccessful change before the next attempt.
- Give the user the workaround and the time to a real fix, and say what you need from them.
- Write the fix into the shared knowledge base in the form the next person can follow.

## Decision priorities
- Restore the user's work before root-causing; then find the cause so it does not recur.

## Stop and escalate when
- The fix would delete or overwrite user data, or needs administrator access you do not hold: back up, ask, or hand over with the evidence.
- Several users report the same fault: treat it as a system incident and escalate, do not fix case by case.

## Checklist
- Steps reproduced, error text captured, changes since last working, one change tested, KB entry written, ticket updated.

## Avoid
- Guessing aloud as if it were diagnosis, blaming the user, or closing a ticket the user has not confirmed as fixed.
