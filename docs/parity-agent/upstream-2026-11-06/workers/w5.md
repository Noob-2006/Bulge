# W5 — subagents, delegation, agent-to-agent

Scope: `crates/seagent-kernel/src/{subagents,agents,coord}.rs`, `crates/seagent/src/ops/rooms.rs`.
All changes are in the working tree; nothing was committed.

## 1. DSH #2 — fork children keep the parent's cached prefix — **done**

What changed:
- `crates/seagent-kernel/src/subagents.rs`
  - Fork children now copy the parent's `System` segments and `Tools` policy verbatim, default to the parent's model/route, and copy every parent request message.
  - A new `EventKind::MessageBoundary` (`event.rs`, `projection.rs`) keeps the child's first task a separate user message, so the child request is a true byte-prefix extension instead of merging into the parent's last user message.
  - Child instructions, agent identity/occupation, context, workspace, output contract and completion guidance now go into that first user message (`fork_brief`) instead of a `subagent` system segment.
  - Tool restrictions are recorded in `EventKind::ToolGuard` and enforced by `tool_guarded` at execution (`kernel.rs` normal tools and code-mode nested tools); the advertised tool list is no longer narrowed for fork children. Blocked child tools still include `ralph`.
  - Session-scoped tools are copied to the fork child so its tool schema matches the parent's too.
- Tests:
  - `agents_tools::forked_child_reuses_the_parent_prefix_and_guards_tools_at_execution`
  - `projection::tests::message_boundary_keeps_consecutive_user_messages_separate`
  - extended `subagents::tests::toolsets_expand_and_policy` for `tool_guarded`

## 2. Hermes #14 — delegation prefix-cache warm-up — **done**

What changed:
- `crates/seagent-kernel/src/subagents.rs`
  - Added `[delegation] prefix_stagger_seconds` (default 0 = off, effective clamp 60 s).
  - `PrefixGate` makes the batch's task 0 the leader; siblings on the same model/base-URL route wait until the leader's first response chunk, the leader finishes, the cap elapses, or cancellation.
  - `Registry` tracks the first chunk per child (`streamed`) and waits on the existing condvar.
- `crates/seagent-kernel/src/kernel.rs`: the streaming callback signals the first chunk once per model call.
- Tests:
  - `agents_tools::prefix_stagger_holds_siblings_until_the_leaders_first_chunk`
  - `subagents::tests::prefix_gate_wakes_on_the_leaders_first_chunk`

## 3. Hermes #15 — agent-to-agent chain bounds — **done**

What changed:
- `crates/seagent-kernel/src/coord.rs`
  - Per-session chain state: hop count, asks already sent, reply target, notify-only sender, 10-minute TTL.
  - `agent_message` returns/delivers a `hop N/max` envelope; past the cap it refuses before delivery.
  - An identical `(recipient, normalized text)` ask twice in one chain is refused.
  - A reply to the agent whose message started the turn is delivered notify-only; messaging that sender back is refused.
- Config:
  - `[delegation] max_hops` (default 4), and the Hermes-compatible `[gateway.bot_loop_guard] max_hops` (wins when set).
- Tests:
  - `coord::tests::agent_message_chains_count_hops_dedupe_asks_and_make_replies_notify_only` (also covers the gateway override and the delegation fallback).

Remaining note: chain state is process-local (like the live sub-agent registry) and session ids make it scoped per conversation; it is not persisted across a daemon restart.

## 4. Hermes #16 — hosted-room lead/auto routing and Continue — **done**

What changed:
- `crates/seagent/src/ops/rooms.rs`
  - Room persists `purpose`, `notes`, `routing` (`everyone|lead|auto`) and `lead_member_id`; old room JSON files load with safe defaults.
  - `create_with`, `set_context`, `rooms create --purpose/--notes/--routing/--lead`, and `rooms update` implement the settings. `rooms show`/summary display them.
  - Purpose and shared notes are rendered in member prompts (and the router prompt), never in the system prompt.
  - Lead routing: an unaddressed, new-thread message first goes to the lead as a routing turn; its `{"assign":[...]}` picks round-0 respondents, with fallback to the lead alone.
  - Auto routing: `Runner::route` on `KernelRunner` uses the `group_router` auxiliary slot (`Config::task_model("group_router")`), strict `{"members":[...]}` / `"everyone"` parsing, fallback to everyone. Assignments are durable `room.assignment` events so planning stays replayable.
  - Continue: `room.continued` grants another full `MAX_ROUNDS`/`MAX_MESSAGES` budget, max 5 per discussion; `rooms continue`, `/room continue <room>`, and the drive loop resume it. Explicit mentions still win over routing.
- Tests:
  - `ops::rooms::tests::room_settings_lead_auto_routing_and_continue`

## 5. DSH runners-up — fresh-context “Ralph” rounds — **done**

Evaluation: this fits as an explicit model-facing tool next to `delegate_task`, not as a change to same-session goals. Goals keep their existing single-session round loop; Ralph is for the user who explicitly asks for fresh-agent iteration.
- `crates/seagent-kernel/src/subagents.rs`
  - New `ralph` tool: one immutable objective, one fresh `plain` child per round, bounded structured report handoff, workspace progress file (`progress_file`, default `<data>/ralph/<run>.md`), round cap and report validation.
  - Config: `[delegation] ralph_max_rounds` (default 16) and `ralph_max_handoff_chars` (default 16384). Children cannot recursively call `ralph`.
  - Result statuses: `complete`, `blocked`, `budget-limited`; ordinary child/report failure is an error naming the round.
- Test:
  - `agents_tools::ralph_runs_fresh_rounds_with_a_bounded_handoff_and_progress_file`
