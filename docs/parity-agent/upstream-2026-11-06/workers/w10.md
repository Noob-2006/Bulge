## 1. Hermes #27 — recover `old_string` pasted with `read`'s `N|` gutter

**Status: done.**

- `crates/seagent-tools/src/fuzzy.rs`
  - Added `strip_line_number_gutter` / `gutter_prefix` / `has_gutter_line`.
  - Gutter recovery runs only after a raw precise match fails and **before** any similarity
    strategy. A recognised gutter paste may only use the precise strategies (or whole-line
    `line_trimmed` for one numbered line); it never falls through to `block_anchor` /
    `context_aware`.
  - Stripping requires that every non-blank line has the gutter, at least one numbered line,
    and consecutive numbering. A `new_string` with an ambiguous/partial gutter is rejected with
    an actionable error instead of guessed.
  - Successful recovery adds a model-facing note; a miss says the prefixes were stripped.
- Tests added in `fuzzy::tests`:
  - `read_line_number_gutter_is_stripped_before_matching`
  - `single_gutter_line_matches_only_a_whole_line_and_never_by_similarity`

## 2. Hermes #7 — checkpoint hardening

**Status: done.**

- `crates/seagent-kernel/src/checkpoint.rs`
  - `Checkpoints::new` refuses `/`, `$HOME`, every ancestor of `$HOME`, the browser-profile
    tree under the data dir, and the checkpoint store itself. Path resolution canonicalises
    the nearest existing ancestor so not-yet-created store/browser dirs compare correctly.
  - Browser-profile directories (`browser/profiles`, `browser/real-profile`,
    `browser/chrome-debug`, `browser/browsers`, `chrome_cdp_profile`,
    `agent-browser-chrome-*`) are in the default exclude list.
  - The per-workspace store is excluded from `git add` by pathspec and un-staged when an
    older index captured it, so a store inside a workspace is never snapshotted into itself.
  - Ignored paths still tracked by an old index are dropped before the file-count and
    size-cap passes, so both limits ignore excluded paths (and `drop_large` only sees
    non-excluded staged files).
  - Rollback uses `git restore --source=<id> --worktree --staged -- . ':(exclude)store'`
    instead of `read-tree`, so a rollback never rewinds the checkpoint store.
- Tests added in `checkpoint::tests`:
  - `refuses_home_parents_browser_profiles_and_the_store_itself`
  - `store_inside_workspace_is_never_staged_or_rewound`
  - `size_and_file_caps_ignore_excluded_paths_already_in_the_index`

## 3. DSH #7 — persistent SSH session

**Status: partial (solid first slice).**

- `crates/seagent-tools/src/exec/ssh.rs`
  - Added `RemoteShell`: one long-lived remote `bash --noprofile --norc` over the existing
    ControlMaster connection. Commands are framed in a subshell with a per-shell nonce and a
    sentinel carrying the exit code, so `exit`/`cd` cannot kill the session and stderr is
    merged. Timeouts/closed connections kill the shell and the next call starts a fresh one.
  - `SshBackend::runner()` (workspace sync, credential upload, pull and other internal
    no-stdin scripts) now uses this persistent shell. Calls that need stdin still use a
    one-shot ssh process (the shell's stdin is the command channel); if the persistent shell
    cannot start, the backend falls back to the old one-shot path. A failure after a command
    was written is returned, never replayed, to avoid duplicating side effects.
  - Workspace sync semantics are unchanged; `cleanup()` shuts the persistent shell down
    before closing the ControlMaster.
  - Test-fixture HOME handling in the existing SSH tests now uses a temp home, so the test no
    longer writes to the real `$HOME`.
- Test added in `exec::ssh::tests`:
  - `persistent_shell_reuses_one_ssh_process_and_frames_exit_status` (fake ssh; two calls,
    only one `bash --noprofile --norc` process, exit status 7 preserved, cleanup closes it).
- Left for a follow-up: the model-facing `shell` tool still spawns one ssh process per call
  because it needs streaming and per-child stdin/PTY; there is still no remote PTY
  (`supports_pty()` remains false). Doing that properly needs a demultiplexed session child
  or a remote helper with separate command/data channels.

## 4. DSH #9 — provider record/replay without a key

**Status: done.**

- `crates/seagent-model/src/replay.rs` (new)
  - JSONL `Exchange` records the provider id, caps, exact request, streamed deltas and final
    response or provider error.
  - `Recorder` wraps a provider and appends exchanges; `ReplayProvider` serves them in order
    and compares the request exactly, naming the first difference on mismatch.
- `crates/seagent/src/providers.rs`
  - `SEAGENT_MODEL_RECORD=<file>` wraps every built provider.
  - `SEAGENT_MODEL_REPLAY=<file>` loads fixtures and serves them before any credential
    resolution or network access (also resolves provider aliases).
- Tests:
  - `replay::tests::a_recorded_run_replays_without_the_inner_provider`
  - `replay::tests::replay_refuses_a_changed_request_and_replays_errors`
  - `providers::tests::replay_fixture_serves_a_provider_without_a_key`
