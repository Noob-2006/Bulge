# W4 — agent loop, context and DeepSeek KV-cache efficiency

Branch/worktree: `w4`. All changes are in the working tree; nothing was committed.

## Item-by-item

### 1. DSH #4 — prefix-stability regression harness — done

Added a kernel integration harness that drives a real multi-step/multi-turn run through the
existing scripted provider and asserts every request's `(system, tools, messages)` is a byte-prefix
extension of the previous request. It uses the exact configuration that used to break the prefix
(`keep_tool_results = 1`, small `max_tool_result_chars`) and proves that below pressure nothing is
rewritten. A separate test covers the documented compaction break by asserting the summary request
replays the routed prefix.

Files: `crates/seagent-kernel/tests/runner.rs`.

Tests: `request_prefix_is_stable_across_steps_and_turns`,
`compaction_summary_replays_the_previous_request_prefix`.

### 2. DSH #1 — compaction summary reuses the warm prefix — done

`compaction::summarise` no longer builds a fresh `summariser` system prompt or a rendered
transcript. It replays the conversation's own system prompt, tool schemas and the shadowed-region
messages, then appends only the summary instruction as the final user message. The summary uses the
conversation route/model by default; only an explicit `[model.tasks] compaction` or
`[auxiliary.compaction]` target overrides the route (and the request still replays the same
prefix). `[model] aux` no longer silently routes compaction to a different model, because that
forfeits the cache reuse this item is about. The retry path, `summary_ok` quality gate and
deterministic fallback are unchanged.

The run loop now prepares the exact step request before checking compaction, so the summarizer
replays the same envelope the provider would have received (including assembly, send-time trimming,
hook modifications and boost). `/compact` and overflow recovery build a prefix when no live request
exists.

Files: `crates/seagent-kernel/src/compaction.rs`, `crates/seagent-kernel/src/kernel.rs`.

Tests: `summarise_replays_the_conversation_prefix_and_appends_only_the_instruction`,
`compaction_summary_replays_the_previous_request_prefix`.

### 3. DSH #3 — trim tool results only under context pressure — done

Default is now pressure-gated: old long tool results are clipped only when estimated/measured
context occupancy crosses `[compaction] prune_threshold`. The pre-existing per-request behaviour is
available as `[compaction] trim_tool_results = "always"`. The pressure calculation is shared with
`maybe_compact`, so both decisions use the same number.

Files: `crates/seagent-kernel/src/kernel.rs`, `crates/seagent-kernel/src/config.rs`,
`crates/seagent-kernel/src/ctxbench.rs` (benchmark now opts into `always` to keep measuring the
trimming benefit).

Tests: `tool_results_are_trimmed_only_under_pressure_unless_configured`,
`trimming_kicks_in_once_context_is_under_pressure`, `cache_policy_keys_default_safely_and_validate`.

### 4. DSH #6 — append system-prompt changes after cached history — done (opt-in)

Added `[model] system_updates = "rewrite" | "in_history"` (default `rewrite`, preserving current
behaviour). On `in_history`, `Runtime::update_system` records a `SystemDelta` event after the
history instead of rewriting the frozen `System` head; projection appends it as a new message at
that point, so the earlier request remains a byte prefix. `/role`, `/personality` and the
persona/SOUL refresh now go through this method.

This is deliberately opt-in because in-history system updates are route-specific and the upstream
report marks public DeepSeek endpoint support as unverified; enabling it by default would be a
silent, unverified wire change.

Files: `crates/seagent-kernel/src/event.rs`, `crates/seagent-kernel/src/projection.rs`,
`crates/seagent-kernel/src/kernel.rs`, `crates/seagent-kernel/src/config.rs`,
`crates/seagent-kernel/src/ctxhost/role.rs`, `crates/seagent-kernel/src/ctxhost/persona.rs`,
`crates/seagent/src/slash.rs`.

Tests: `system_prompt_changes_append_after_history_when_configured`,
`system_delta_appends_after_cached_messages`, `cache_policy_keys_default_safely_and_validate`.

### 5. DSH #8 — log enough to replay exact request bytes — done

Every provider send now appends a durable `Request { purpose, request }` event containing the full
`ModelRequest` after all send-time transformations: trimming, image preparation/eviction, thinking
settings, fast tier, middleware rewrites, fallback model and boost. Conversation, compaction and
micro-compaction requests are logged. PII-at-rest masking is applied to the text in these events
when enabled. This increases session-log size by roughly one request envelope per attempt; that is
the cost of exact replay.

Files: `crates/seagent-kernel/src/event.rs`, `crates/seagent-kernel/src/kernel.rs`,
`crates/seagent-kernel/src/term.rs`.

Tests: `session_log_replays_the_exact_request_bytes`,
`the_session_log_records_the_post_image_prep_request`.

### 6. Hermes #1 — drop a safety-refused turn from model context — done

On `StopReason::Refusal` the kernel now records `TurnDropped { from_seq, upto_seq, reason }` for the
refused exchange and a warning notice telling the user it stays in the transcript but is no longer
sent. Projection skips that seq range when building the model context, so later requests do not
re-judge the refused turn. Raw `Message` events remain in the log, and the event-driven TUI still
displays them; projection-based transcript exports deliberately show model context.

Files: `crates/seagent-kernel/src/event.rs`, `crates/seagent-kernel/src/projection.rs`,
`crates/seagent-kernel/src/kernel.rs`, `crates/seagent/src/term.rs`.

Tests: `a_refused_turn_is_dropped_from_later_model_requests`,
`turn_drop_hides_only_the_model_context`.

### 7. Hermes #2 — UNVERIFIED hypotheses survive compaction — done

`## Unverified / Working Hypotheses` is now part of the summary contract (`HEADINGS`), the
instruction asks for `UNVERIFIED: <claim> — <basis so far>` lines and `None.` when empty, and the
deterministic fallback emits the heading too.

Files: `crates/seagent-kernel/src/compaction.rs`.

Tests: `summary_prompt_requires_unverified_hypotheses` (the prefix-replay test also asserts the
heading reaches the real summarizer request).

### 8. Hermes #37 — label a defaulted context window — done

Added `contextpin::is_fallback` / `marker`. `/context` text and JSON, the kernel-side `/context`,
`/status` and the dock snapshot now show `(fallback)` when the window is only the generic default
because no local source knows the model; `(pinned)` still wins. `Runtime::window` now also honours
`model.context_length` as the documented pin (it previously ignored it in the kernel thresholds).

Files: `crates/seagent-model/src/contextpin.rs`, `crates/seagent-kernel/src/kernel.rs`,
`crates/seagent-kernel/src/ctxhost/slash.rs`, `crates/seagent/src/ops/context.rs`,
`crates/seagent/src/slash.rs`, `crates/seagent/src/agentcmds/status.rs`,
`crates/seagent/src/ops/dock.rs`.

Tests: `defaulted_windows_are_labelled_and_known_ones_are_not`,
`context_report_marks_a_defaulted_window`, `a_pinned_context_window_is_labelled_and_wins`.

## Notes / remaining

  mechanism itself is complete and tested.
- Request logging is intentionally verbose (full envelope per attempt). If log growth becomes a
  problem, a compact header + changed-message delta would be the next step, but that would need a
  replay checker to stay honest.
- No new third-party dependencies were added.
