# W9 — CLI/TUI and web console UX

Status: 6 done, 1 partial. No new dependencies; no public CLI flags or config keys were
changed. The only out-of-area edits are the small `checkpoint.rs` helper, the two
`security_cli.rs` helpers exposed to the console, and the `session.handoff` host method.

## 1. OpenClaw-core #5 — console standing grants + exec policy — **partial**

What changed:
- `crates/seagent/src/ops/ui_methods.rs`: new `ui.approvals.grants.list`,
  `ui.approvals.grant.revoke`, `ui.exec.policy.get`, `ui.exec.policy.set`.
  Grants list merges durable grants with the read-only config allowlists; revoke goes
  through `seagent_security::approvals::remove_grant`.
- `crates/seagent/src/security_cli.rs`: exposed `exec_policy_json` and added
  `set_exec_policy` (same validation/rollback path as `seagent exec-policy set`).
- `ui/web/ops.js`: Approvals page now has a "Standing grants" section with revoke
  buttons, an exec-policy editor (security / ask / ask-fallback), and a per-agent table
  showing the effective role approval, exec, sandbox and tool restrictions.
- `ui/web/index.html`, `ui/web/app.js`: no nav change for this item (it lives in Approvals).

Tests: `ops::ui_methods::tests::approvals_grants_exec_policy_and_security_posture`.

Left: editing an exec policy *per named agent* is not possible because SE Agent has no
per-agent exec config key (only the global `[approvals.exec]` and role presets). The
console shows each agent's effective role policy and can enforce the global policy or a
role's `approval = strict`; adding a per-agent override would need a new engine-read
config key and is recorded as remaining work rather than faked.

## 2. OpenClaw-core #6 — console security posture page — **done**

What changed:
- `crates/seagent/src/ops/ui_methods.rs`: `ui.security.status` returns every exposure
  surface (app server + channel listeners) with loopback/auth/TLS/proxy/rate-limit
  facts, `exposure::findings` and warnings, app endpoints and scoped-token metadata
  (never token values), channels (open/allowlisted, signed, listening), plugin/MCP
  counts, and per-agent capabilities. Unknown roles are returned as `status: unknown`.
- `ui/web/ops.js`: new `VIEWS.security` page in the existing style (KPI row, surfaces,
  app/tokens, findings, channels, agents).
- `ui/web/index.html` + `ui/web/app.js`: new "Security / 安全" nav item and view.

Tests: `approvals_grants_exec_policy_and_security_posture` (asserts loopback surface,
findings, exec posture, unknown role never looks safe); `ui::tests::operations_views_are_served`
now checks the new view/nav/methods are served.

## 3. Hermes #8 — `/undo` changed files + checkpoint id — **done**

What changed:
- `crates/seagent-kernel/src/checkpoint.rs`: `Checkpoints::changed_files(id)` lists
  modified/deleted tracked files plus new untracked files against a checkpoint, read-only.
- `crates/seagent/src/slash.rs`: `rewind_turns` reads the checkpoint taken when the oldest
  undone turn started, then appends a `changed files (checkpoint <id> restores them;
  /undo <id>)` block. No checkpoint for that exact turn means no false promise.

Tests: `checkpoint::tests::changed_files_lists_tracked_edits_deletions_and_new_files`;
`agentcmds::tests::undo_names_changed_files_and_the_checkpoint_that_restores_them`.

## 4. Hermes #9 — rewind picker (Esc Esc) — **done**

What changed:
- `crates/seagent-app/src/tui/rewind.rs`: newest-first prompt picker, skips prompts with
  attachments, maps a selection to `/undo N` / `/branch --at N`.
- `crates/seagent-app/src/tui.rs`: Esc Esc (coalesced or two taps within 500 ms), arrow

- `crates/seagent-app/src/tui/actions.rs`: `local session` action now adopts a fork and
  `reload_current` refreshes the transcript after rewinds.

Tests: `tui::rewind::tests::*`, `tui::tests::rewind_picker_undoes_to_the_picked_prompt_and_prefills_it`,
`tui::actions::tests::branch_session_action_switches_to_the_fork`.

## 6. Hermes #24 — `/new` mid-turn backgrounds the old turn — **done**

## 7. Hermes section B — `/handoff` — **done**

What changed:
- `crates/seagent/src/agentcmds/handoff.rs`: `/handoff <channel>[:<chat>]` resolves the
  target (default_chat fallback), refuses mid-turn, binds the chat to the session in the
  daemon router, posts a handoff message, and records a session notice. A CLI process has
  no channel hub, so it calls the daemon instead.
- `crates/seagent/src/agentcmds/mod.rs`: registered `/handoff`.
- `crates/seagent/src/main.rs`: new `session.handoff` host method (and `HOST_METHODS` entry)
  so `seagent chat` can hand off through the running daemon.

Tests: `agentcmds::handoff::tests::resolves_channel_chat_and_default`,
`agentcmds::handoff::tests::perform_binds_the_chat_and_posts_the_handoff`.
