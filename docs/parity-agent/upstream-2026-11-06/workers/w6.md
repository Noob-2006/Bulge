# W6 — model providers and per-step stats

All changes are in the working tree; nothing was committed, pushed or checked out.

## 1. Bedrock discovery: on-demand filter + inference profiles — done

**What changed**
- `crates/seagent-model/src/bedrock.rs`: discovery now filters bare foundation
  models whose `inferenceTypesSupported` is present and lacks `ON_DEMAND`
  (missing/empty metadata stays selectable), pages through
  `/inference-profiles`, keeps only `ACTIVE` profiles, de-duplicates, and keeps
  explicitly configured `models` ids unfiltered. A failed profile call degrades
  to the foundation list instead of hiding everything.
- `crates/seagent-model/src/bedrock.rs` tests.

**Tests**
- `bedrock::tests::discovery_hides_non_on_demand_foundations_and_lists_profiles`
  (fake control-plane endpoint; pagination, inactive profile, empty/non-ON_DEMAND
  foundation, explicit id).

## 2. Ambient AWS credentials in `sigv4.rs` — done (first solid slice)

**What changed**
- `crates/seagent-model/src/sigv4.rs`: `AwsCreds::from_env` now follows the AWS
  default chain: environment → web identity (EKS IRSA via STS) → shared
  credentials/config profile (including `credential_process`) → ECS container
  credentials → EC2 IMDSv2. Added safe handling for partial env pairs,
  `AWS_SHARED_CREDENTIALS_FILE`, `AWS_CONFIG_FILE`, `AWS_PROFILE`,
  `AWS_WEB_IDENTITY_TOKEN_FILE`/`AWS_ROLE_ARN`/`AWS_ROLE_SESSION_NAME`,
  `AWS_ENDPOINT_URL_STS`, `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI`/
  `AWS_CONTAINER_CREDENTIALS_FULL_URI` (+ auth token/file),
  `AWS_EC2_METADATA_SERVICE_ENDPOINT` and `AWS_EC2_METADATA_DISABLED`.
  IMDS uses a v2 token for every read; metadata/ECS loopback requests are direct
  and refuse redirects.
- `crates/seagent-model/src/sigv4.rs` tests.

**Tests**
- `sigv4::tests::ecs_container_credentials_from_fake_endpoint`
- `sigv4::tests::imds_v2_token_role_and_credentials_from_fake_endpoint`
- `sigv4::tests::web_identity_exchanges_the_token_file_at_fake_sts`
- `sigv4::tests::chain_order_and_partial_environment`
- `sigv4::tests::shared_profile_selects_the_named_profile`

**Left**
- Ambient metadata/web-identity credentials are resolved per model request; no
  expiry-aware process cache yet. Functionality is complete, but this can add a
  metadata/STS round-trip per step on EC2/EKS.

## 3. Rerank Decision provider — done

**What changed**
- `crates/seagent-kernel/src/decision.rs`: new `rerank` decision backend that
  maps boolean/choice/sort questions onto `/rerank` calls, groups questions by
  query, retries `documents` → `texts` (remembering the accepted field), accepts
  Cohere/Jina/vLLM/Infinity `{results}`, Voyage `{data}` and TEI bare arrays,
  requires one score per document in `[0,1]`, and rejects unsupported question
  types or invalid responses instead of inventing answers.
- `DecisionConfig.backend` documentation and module header updated.

**Tests**
- `decision::tests::rerank_plan_and_scores_map_boolean_choice_and_sort`
- `decision::tests::rerank_decisions_retries_texts_and_maps_the_response`
- `decision::tests::decision_evaluate_rerank_backend_posts_and_maps_the_answer`

## 4. Native DeepSeek Messages route — done, real endpoint unverified

**What changed**

## 5. Per-step timing and cache stats — done

**What changed**
- `crates/seagent-kernel/src/event.rs`: new durable `Step` event with turn, step,
  model, `ttft_ms`, `model_ms`, `tool_ms`, `tool_calls` and usage.
- `crates/seagent-kernel/src/kernel.rs`: records TTFT from the first streamed
  text/thinking chunk, full model time, tool execution time, tool count and the
  step's usage after tools settle. Step events are not part of the model-visible
  projection.
- `crates/seagent/src/agentcmds/sessions.rs`: `seagent session stats` now prints
  a fleet step summary, and `seagent session stats --session <id>` prints each
  step's TTFT, output tok/s, model/tool time and cache hit rate (plain text and
  `--json`). `crates/seagent/src/term.rs` labels the new event.
- `docs/MANUAL.md` documents the new `--session` view.

**Tests**
- `runner::per_step_stats_recorded_with_timing_and_cache_usage`
- `agentcmds::sessions::tests::stats_show_per_step_ttft_speed_time_and_cache`

## 7. Daybreak / Gemini tiers / Qoder / OAuth gaps — done

**What changed**
- `crates/seagent-core/src/types.rs`, `crates/seagent-kernel/src/config.rs`,
  `crates/seagent-kernel/src/context.rs`, `crates/seagent-model/src/responses.rs`:
  new opt-in `[model] daybreak = true`, sending
  `access_programs.cyber = "daybreak_blue"` only on the Codex quirk route.
- `crates/seagent-model/src/gemini.rs`: `generationConfig.serviceTier` maps
  `priority`/`fast`/`ultrafast` → `priority`, `flex` → `flex`,
  `standard`/`normal` → `standard`.
- `crates/seagent-app/src/acp_client.rs`: added the `qoder` preset
  (`qodercli --acp`).
- `crates/seagent-model/src/login.rs`: xAI OAuth now requires a safe,
  response-derived access-token lifetime (`expires_in` or JWT `exp`), rejects
  missing/zero/negative/overflowing values, and publishes the fresh expiry on
  refresh instead of retaining a stale one.
- Anthropic token-profile collisions: verified that our store keys logins by
  kind + flow + label, so a setup-token login cannot overwrite an API-key
  profile. Added a regression test; no production change was needed for that
  part.

**Tests**
- `responses::tests::daybreak_is_explicit_and_codex_only`
- `gemini::tests::service_tier_maps_flex_priority_and_standard`
- Extended `acp_client::tests::config_presets_and_modes`
- `login::tests::xai_oauth_requires_a_usable_response_expiry`
- `store::tests::setup_token_does_not_collide_with_an_api_key_profile`

**Unverified**
- Daybreak is sent for opted-in Codex requests without first reading the
  account's Codex catalog, so entitlement checking on a real account is
  unverified. Accounts without the program may reject the request.
