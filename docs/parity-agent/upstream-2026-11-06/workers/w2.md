# W2 — secret redaction and browser

## 1. Hermes #3 — redaction expansion — **done**

Expanded `mask_secrets` (`crates/seagent-security/src/risk.rs`) beyond the existing token/PEM
prefixes to cover:

- database connection strings: `scheme://user:pass@host` (Postgres/MySQL/MongoDB/Redis/AMQP)
  and ADO.NET/ODBC/JDBC `Password=`/`Pwd=` plus libpq `password=` conninfo, using the same
  quote/brace/`;`/backslash value grammar as upstream;
- `PGPASSWORD`, `MYSQL_PWD`, `SSHPASS` and ENV-shaped secret assignments;
- general URL userinfo `scheme://user:pass@host`, keeping placeholders such as
  `${DB_PASS}`, `<password>`, `{pw}` intact;
- PGP armoured keys, PuTTY `.ppk` `Private-Lines:` bodies and `AGE-SECRET-KEY-1…`;
- Azure `AccountKey`/`SharedAccessKey`/`SharedAccessSignature` (spaced source assignments
  such as `this.accountKey = config.Key` are left alone);
- quoted YAML/JSON secret values (including one level of JSON-string escaping), gated by
  credential-shaped key names and value shape so `Secretary:`, `tokenizer:`, `max_tokens:`
  and JSON snippets such as `"apiKey": "os.getenv('X')"` are not over-masked;
- `--password`/`--token`/`--api-key`-style flags, keeping help metavars (`--token TOKEN`),
  `$VAR` references and numeric timeouts readable.

`secret_kind` now shares the same patterns as `mask_secrets`, so the egress/exfil checks and
the output mask cannot drift. `trajectory::redact_patterns` applies the expanded mask to
force-mode exports, with its existing token and `Authorization: Bearer` rules retained.

Files: `crates/seagent-security/src/risk.rs`, `crates/seagent-kernel/src/trajectory.rs`.

Tests: `risk::tests::{connection_strings_are_masked_in_all_forms,
env_assignments_and_flags_are_masked_without_touching_help_text,
non_pem_private_keys_and_azure_keys_are_masked,
quoted_json_and_yaml_secret_values_are_masked}` (the last includes escaped JSON and
placeholder false positives); `trajectory::tests::redaction_and_ids` extended.

## 2. OpenClaw-ext #1 — mask sensitive snapshot values — **done**

Added `snapshot::redact_sensitive_ax_values` (`crates/seagent-browser/src/snapshot.rs`):
valued `textbox`/`combobox`/`searchbox`/`spinbutton` nodes are resolved through
`DOM.describeNode`; `type=password` and `autocomplete` tokens `current-password`,
`new-password`, `one-time-code`, `cc-number`, `cc-csc` are replaced with `[redacted]`.
Rendered text descendants are masked too. A field that cannot be resolved (missing backend
node, DOM call failure) is masked fail-closed; ordinary fields keep their values.

Wired into both snapshot paths:
- AI/role snapshots in `actions::snapshot` (main frame and spliced child frames);
- raw ARIA snapshots in `openclaw.rs`.

Files: `crates/seagent-browser/src/{snapshot.rs,actions.rs,openclaw.rs}`.

Tests: `snapshot::tests::sensitive_ax_values_are_masked_before_render`;
`tests_actions::openclaw_snapshots_mask_password_otp_and_card_values` (AI and ARIA formats
against the fake CDP page, with a benign email value still readable).

## 3. OpenClaw-ext security — redirect hops and tab close — **done**

`browser.allow_private_urls = false` is now strict for every transport (previously a local
browser bypassed the explicit `false`). Under strict policy, `tools::navigate` installs a CDP
`Fetch` fence for `Document` requests and checks each hop before Chrome sends it; blocked
hops are failed with `BlockedByClient` and reported. If the fence cannot be installed, or the
transport is Camofox (REST API, no hop interception), strict http(s) navigation is refused
with an explicit "requires redirect-hop inspection" error instead of relying on an
after-the-fact final-URL check. The existing `check_final_url` remains as a second line.

Tab close is verified exempt: neither `action=close` nor the act `close` kind consults the
URL policy, so a tab that later moved to a blocked destination can still be closed.

Files: `crates/seagent-browser/src/{policy.rs,engine.rs,tools.rs}`.

Tests: `policy::tests::strict_policy_checks_local_targets_and_uninspectable_redirects`;
`tests_actions::strict_navigation_refuses_a_private_redirect_hop`;
`tests_actions::tab_close_is_exempt_from_strict_url_policy`.

Residual: action-triggered navigations (click/JS in `browser_act`) still use the final-URL
check; only explicit `open`/`navigate` install the per-hop fence. OOPIF child sessions are
not individually fenced. This is a safe follow-up slice, not a stub: the direct navigation
path fails closed and uninspectable transports are refused.
