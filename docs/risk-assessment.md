# ark 風險自評（依數發部《人工智慧風險分類框架》v1.0）

框架：數位發展部《人工智慧風險分類框架》v1.0（中華民國 115 年 7 月 7 日，依《人工智慧基本法》第 16 條訂定），表 1「AI 風險類型表」3 大類 20 子類。來源：https://www-api.moda.gov.tw/File/Get/moda/zh-tw/UieEfux5Yv0iJuR
（子類名稱由 PDF 抽取後重組，標點以原檔為準。）

**定位**：ark 是自架的 agent 執行環境，不訓練模型、不提供模型。
- **開發者**（ark）提供控制機制。
- **部署者**（安裝 ark 的人或組織）決定接哪個模型、開放給誰、做什麼用途。
- 下表的「責任」欄標示主要由誰負責。

評等：
- **高**：直接相關，已實作控制
- **中**：部分相關，或有控制但需部署者設定
- **低**：主要屬於模型或社會層面，ark 無法實質控制

## A：AI 系統本身之技術設計缺陷

| 代碼 | 子類 | 相關 | ark 的控制措施 | 責任 | 殘餘風險／部署者應做 |
|---|---|---|---|---|---|
| A1 | AI 系統的安全漏洞與攻擊 | 高 | **權限與閘門**：提權與外送兩道閘門；`NoNewPrivileges`；工具輸出與 MCP 描述的 prompt injection 掃描；untrusted MCP 需核准。<br>**對外介面**：webhook／channel 驗簽章（常數時間比對）；app token、per-peer A2A token；裝置 Ed25519 簽章＋配對。<br>**本機防護**：CSP、Origin 檢查、0600 檔案權限；HTTP 伺服器有大小與時間限制，防慢速連線。 | 開發者 | 保持更新；不要把 App Server 綁到公網而不經反向代理與 TLS。 |
| A2 | 缺乏透明性或可解釋性 | 中 | 每個 session 有完整、不可省略的事件紀錄（工具呼叫、參數、結果、閘門判定、成本）；ACP／Web UI 即時顯示工具與 diff；`ark session show`。 | 雙方 | 模型本身的推理仍是黑箱；需要時保存紀錄供稽核。 |
| A3 | AI 行為偏離人類意圖與社會價值 | 中 | goal／budget／max_steps 上限；卡住偵測；`/stop` 與中斷；hooks 可以阻擋或改寫工具呼叫。 | 雙方 | 撰寫明確的 identity 與指示；用 hooks 加上組織政策。 |
| A4 | AI 具有危險的能力 | 中 | 能力受工具集限制，可停用工具（`[tools] disabled`）；shell 經閘門；子 agent 有深度與預算限制；node 指令由裝置端政策決定。 | 雙方 | 只開需要的工具與 channel；node 的 `system.run` 預設為 `deny`。 |
| A5 | 影響隱私與違反個人資料保護法規 | 高 | 外送閘門擋下秘密與個資；`privacy_notice`；`retention_days`；`ark data export/delete`；DM 預設拒絕陌生人；秘密放 vault，不進紀錄。 | 部署者為主 | 依個資法告知、限定目的；評估跨境傳輸（見 compliance-tw.md）。 |
| A6 | 侵害智慧財產權疑慮 | 低 | 無特定控制（ark 不訓練模型）；web_fetch 會標示來源 URL。 | 部署者 | 注意生成內容與引用來源的授權。 |
| A7 | 不公平的歧視或偏見 | 低 | 屬於模型特性；可切換或多模型備援。 | 部署者 | 高影響決策不要只依賴模型。 |
| A8 | 錯誤或誤導訊息 | 中 | `ai_label` 標示 AI 生成；工具結果與來源可追溯；回覆可附註停止原因（預算、步數）。 | 雙方 | 在對外 channel 開啟 `ai_label`，並提醒使用者查證。 |

## B：部署後操作及人機互動問題

| 代碼 | 子類 | 相關 | ark 的控制措施 | 責任 | 殘餘風險／部署者應做 |
|---|---|---|---|---|---|
| B1 | 過度依賴與不安全使用 | 中 | 閘門在高影響動作時要求人確認；ask_user 讓 agent 主動提問；不確定時要求說明假設。 | 部署者 | 醫療、法律、財務情境需人工複核。 |
| B2 | 喪失人類自主性 | 中 | 只有兩道閘門，但永遠可以設為 `deny`；所有自動化（cron、goal、channel）都能 `/stop`、`ark daemon stop`；核准紀錄可追溯。 | 部署者 | 決定哪些工作可以全自動。 |
| B3 | 生成違法內容 | 中 | hooks（pre_tool／post_tool）可接內容審核；channel 可限制使用者與群組。 | 部署者 | 對公眾開放時加上輸出審核 hook 與使用規範（AUP）。 |
| B4 | 詐欺與深偽技術濫用 | 低 | ark 不內建語音或影像合成；對外訊息都經 channel 身分送出，且可加 AI 標示。 | 部署者 | 不要用 ark 冒充他人。 |
| B5 | 用於網路攻擊 | 中 | shell 經閘門（提權、外送）；hooks 可封鎖特定指令；egress_deny 清單。 | 雙方 | 共用主機上不要開放 `group_policy = "open"` 加上 shell 工具。 |
| B6 | AI 自主代理之授權外行為 | 高 | 兩道閘門（提權、外送）且不可被模型繞過；untrusted MCP；成本與步數上限；子 agent 深度限制；A2A 對方訊息標記為「非操作者指令」；node 指令由裝置端白名單決定；專案設定未受信任時不載入 hooks／MCP／channels；kill switch：`/stop`、`ark daemon stop`、systemd stop。 | 開發者 | 定期檢視 session 紀錄與閘門紀錄。 |

## C：社會結構與環境衝擊

| 代碼 | 子類 | 相關 | ark 的作法 |
|---|---|---|---|
| C1 | 企業及國家間競爭秩序失衡 | 低 | 不適用於單一工具；ark 有完整的自動測試與實測紀錄後才發佈。 |
| C2 | 權力集中與利益分配不公平 | 低 | 自架、開源（MIT）、可接任何供應商或本地模型，降低單一廠商依賴。 |
| C3 | 不平等加劇、就業品質下降 | 低 | 屬於部署者的組織決策。 |
| C4 | 人類在經濟與文化上之創作價值受損 | 低 | 屬於部署者的用途決策。 |
| C5 | 環境傷害 | 低 | 省 token 設計（漸進揭露、快取、壓縮）降低用量；可改用小模型做輔助工作。 |
| C6 | 認知作戰與資訊主權 | 中 | `profile = "government"` 拒絕中國境內的模型與主機；所有資料留在部署者自己的機器。 |
